# UX-19 — l'Atelier choisit sa collection avant son album

**Arrêté sur** — rien de codé. Fiche ouverte le 2026-10-21 sur une demande de Hugo, ses trois
réponses prises le même jour (Contexte).

## Reste

### Le sélecteur
- [ ] Dans l'Atelier, un sélecteur « Collection » précède « Album », du même patron que lui (un `<select>` natif, son libellé) — attendu : sous un compte qui lit plusieurs collections du projet courant, la liste *Collection* les propose toutes, la base en tête, et la liste *Album* ne montre que les albums rangés dans la collection choisie ; un album rangé dans deux collections apparaît dans chacune
- [ ] Un choix « Toutes les collections du projet » rend la liste d'aujourd'hui — attendu : choisi, la liste *Album* est celle du projet courant, comme avant ce chantier
- [ ] Quand rien n'a été choisi, l'Atelier s'ouvre sur la collection de BASE du projet ; si on ne la lit pas, sur la première collection qu'on lit — attendu : un compte qui arrive, entré dans le projet par sa base, voit d'emblée les albums de la base, et rien d'autre
- [ ] Le choix est un filtre de l'ATELIER, retenu par lui seul, projet par projet — attendu : choisir « Étude B », recharger : « Étude B » revient ; changer de projet dans la bande du haut : la base du nouveau projet ; la Bibliothèque n'en est pas changée. Stockage local sous try/catch : sans lui, l'Atelier s'ouvre sur la base, sans erreur
- [ ] Une collection où l'on ne lit aucun album le dit dans la liste *Album*, sans laisser un album d'avant affiché

### L'adresse
- [ ] Un lien `/?album=<id>…` vers un album absent de la collection choisie la change pour une collection qui le contient — attendu : l'album s'ouvre, et la liste *Album* le contient ; jamais un album ouvert hors de la liste
- [ ] Ouvrir un album depuis la fiche d'une collection de la Bibliothèque pose cette collection dans l'Atelier — attendu : depuis « Étude B », l'Atelier s'ouvre avec *Collection* = « Étude B », même si l'album vit aussi ailleurs

### Ce qui ne doit pas changer
- [ ] À 320 px et à grande police, la barre de l'Atelier ne déborde pas avec un sélecteur de plus — attendu : la mesure de reflow existante passe, et l'œil le confirme à la passe
- [ ] Les tests navigateur de l'Atelier passent, réécrits là où ils choisissaient un album dans la liste entière du projet — attendu : chaque réécriture dit pourquoi dans le commit

## Contexte

**La demande** (Hugo, 2026-10-21) : dans l'Atelier, la liste *Album* montre tous les albums du
projet courant. Avec 150 albums en stock, et autant de collections qui se recoupent, un
nouvel arrivant ne sait ni où il est ni ce qu'on attend de lui. La Bibliothèque pense déjà en
collections — la collection y est un CALQUE posé sur le corpus (`UX-18`) — ; l'Atelier était
le seul écran qui ne le faisait pas.

**Les trois réponses de Hugo, le 2026-10-21 :**
1. La collection choisie est un FILTRE de l'Atelier, pas une « collection courante » partagée
   avec la Bibliothèque comme l'est le projet. Venir d'une collection de la Bibliothèque la
   pose par l'adresse ; rien de neuf n'est retenu ailleurs.
2. Rien de choisi : la collection de BASE du projet (celle où ses membres entrent).
3. La forme suit le patron existant — un second `<select>` natif avant *Album* ; Hugo la juge
   à la passe, sans maquette.

Le choix « Toutes les collections du projet » n'a pas été posé à Hugo : il est ajouté pour que
la liste d'aujourd'hui reste atteignable, et se retire d'une ligne s'il ne le veut pas.

**Ce qui reste hors de ce chantier** : chercher dans une liste de 150 albums (une recherche
dans le sélecteur se trancherait, elle, sur maquette) ; l'écran « par où commencer »
(`UX-6`, décalé par Hugo le même jour).
